# 软件杯教育版需求规格说明书

| 项目 | 内容 |
|---|---|
| 文档版本 | 1.0 |
| 更新日期 | 2026-07-19 |
| 适用范围 | 软件杯教育版桌面 Web 三端 |
| 系统组成 | `server`、`admin-web`、`employee-web` |

## 1. 产品目标

Learning Agent Hub 面向高校课程学习场景，通过课程知识库、对话式学生画像、动态学习路径和多智能体资源生成，为不同基础、目标和学习节奏的学生提供可解释、可追溯的个性化学习资源。首门完整示范课程固定为《Java Web 应用开发》。

## 2. 角色与数据范围

| 角色 | 核心能力 | 数据范围 |
|---|---|---|
| 学生 | 学习课程、完成画像、查看学习路径、生成资源、完成测验 | 仅本人画像、路径、作答、生成任务和已发布课程资源 |
| 教师 | 创建课程、维护章节文章、上传课程资料、审核资源、查看学情 | 仅本人创建或通过邀请加入协作的课程 |
| 教育运营管理员 | 配置模型、智能体、知识库、权限、内容安全、文件和审计 | 按后台角色权限和操作权限控制 |

教师协作采用 `OWNER/COLLABORATOR` 模型。所有者可删除课程和生成单次邀请；协作者可编辑课程、章节、资料和资源，但不能删除课程或继续邀请其他教师。

## 3. 核心业务场景

### 3.1 课程学习

- 学生以网格或列表查看已发布课程。
- 课程详情包含简介、目标、先修要求、章节文章、测验、学习路径和推荐资源。
- 章节文章支持文字、标题、列表、引用、代码块、图片、视频、表格和附件混排。
- Word、PowerPoint 自动异步转换为 PDF 只读预览，并保留原文件下载。

### 3.2 教师课程管理

- 教师创建课程时维护课程编码、名称、简介、封面、学时、目标、先修要求和发布状态。
- 教师编排章节、知识点和知识点依赖，并在独立文章页维护正文。
- 教师上传资料并关联章节和知识点，页面展示解析、分块、向量化和入库进度。
- 教师可通过限时单次邀请添加协作教师。

### 3.3 对话式画像

- 系统以自然语言逐项采集知识基础、学习目标、掌握程度、易错点、认知风格、资源偏好、学习节奏和实践能力。
- 每个维度展示结论、置信度、证据和更新时间。
- 测验结果自动更新掌握程度和易错点；学生可主动纠正画像结论。

### 3.4 个性化学习路径

- 路径依据知识点依赖、当前画像和知识点掌握度生成。
- 节点展示目标、资源、预计时长、完成条件、状态和推荐理由。
- 学生按顺序完成节点；测验结果生成新的活动路径版本，旧版本保留。

### 3.5 多智能体资源生成

- 固定画像分析、路径规划、内容生成、练习生成、事实校验五个角色。
- 每次任务生成讲解文档、思维导图、练习题、代码实操和拓展阅读。
- 页面展示任务百分比、当前角色、步骤结果、失败原因和重试入口；刷新后可恢复。
- 生成内容必须保留知识库引用、模型、画像版本、耗时和校验结论。

### 3.6 教师审核与运营

- 低置信度或待复核资源不能直接发布。
- 教师可修改、通过、拒绝、发布、撤回和定向推送资源。
- 学情页面展示课程完成率、平均掌握度、薄弱知识点、风险学生、班级状态和资源使用情况。

## 4. 管理端需求

- 运营概览：用户、任务、知识库和系统状态概览。
- AI 任务：任务筛选、详情、工具调用、审计轨迹、失败聚合和超时扫描。
- AI 助手：版本、DAG、模型和知识库绑定管理。
- 知识库：文件上传、入库阶段、进度、失败重试和检索测试。
- AI 基座：模型供应商、模型、连接测试和默认模型配置。
- 内容安全：提示词注入检测、阻断标记和复核阈值。
- 用户与班级、角色权限、权限点、文件空间、消息投递、审计日志和通知设置。

## 5. 非功能需求

- Java 17、Spring Boot 3 模块化单体、Vue 3 双前端；物理交付为后端、管理端和学生/教师端三项。
- 所有写接口完成认证、角色、操作和数据范围控制。
- 课程创建、测验提交、资源生成、推送和入库支持幂等。
- 外部模型调用不进入长数据库事务，且只发送最小化、脱敏后的学习上下文。
- 页面覆盖加载、空数据、失败、无权限、长文本和长任务状态。
- 比赛提交范围聚焦桌面 Web，核心页面不存在横向溢出、遮挡或不可操作入口。
- 数据库只通过 Flyway 增量迁移，不清空或重建现有数据库。

## 6. 验收主流程

1. 学生登录并通过对话形成 8 维画像。
2. 系统为《Java Web 应用开发》生成首版学习路径。
3. 学生选择薄弱知识点创建个性化资源任务。
4. 五个智能体完成检索、规划、生成、练习和事实校验。
5. 教师查看引用与校验结果，审核并发布资源。
6. 学生学习资源并完成课程测验。
7. 掌握度、画像和学习路径生成可追溯的新版本。
8. 教师在学情页面查看学生变化并定向推送后续资源。

## 7. 不进入比赛主线

- 考勤、请假、人事审批和岗位治理不进入教育版导航与演示流程。
- 不拆分微服务，不建设平台级多租户，不同时建设多门完整课程。
- 文件和消息治理仅作为管理端次级运维能力保留。
