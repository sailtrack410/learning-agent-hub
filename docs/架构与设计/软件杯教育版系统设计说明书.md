## 1. 总体架构

系统采用 Spring Boot 3 模块化单体和 Vue 3 双前端：

- `server`：课程、画像、评估、路径、资源、Agent、RAG、认证、权限、文件、消息和审计。
- `employee-web`：根据登录角色呈现学生学习端或教师课程端。
- `admin-web`：教育运营管理端。
- MySQL：业务真相源；PostgreSQL + pgvector：知识向量；Redis：会话与短期状态；MinIO/本地存储：文件对象。

模块间写入调用数据所属模块 Service，统计只读查询在明确查询服务中聚合。外部模型、文件转换和知识入库均在事务提交后异步执行。

## 2. 教育业务模块

| 模块 | 数据责任 | 公共入口 |
|---|---|---|
| `course` | 课程、章节、知识点、协作教师、资料关联 | 学生课程查询、教师课程管理、资源权限 |
| `profile` | 画像维度、版本、证据、对话 | 当前画像、回答、纠正、测验联动 |
| `assessment` | 测验、题目、作答、掌握度 | 测验查询、幂等提交、诊断 |
| `learningpath` | 路径版本、节点、推荐、进度 | 查询/生成路径、完成节点、测验后重排 |
| `learningresource` | 生成任务、角色步骤、资源、引用、审核、推送 | 学生生成与查看、教师治理 |
| `learningdashboard` | 学生首页只读聚合 | 今日任务、进度、掌握度、练习和推荐 |
| `ragflow` | 课程知识空间、文档、切片、向量和检索 | 异步入库、阶段进度、检索 |

## 3. 课程与文章设计

课程发布状态为 `DRAFT/PUBLISHED`。章节正文统一为 `ARTICLE`，内容保存为 Tiptap JSON。图片、视频和附件节点只保存 `attachmentRefId` 等业务属性，文件内容由文件模块维护。

Office 附件预览流程：

1. 教师上传课程附件。
2. 预览提交接口校验教师角色、课程参与关系、资源归属、类型和大小。
3. `sys_attachment_preview` 进入 `CONVERTING`，事务外业务线程调用 LibreOffice。
4. PDF 写入对象存储并创建独立附件引用，状态改为 `READY`。
5. 页面轮询状态，完成后嵌入 PDF；原附件仍用于下载。

重复请求复用活动任务或已生成 PDF，失败状态保留原因并允许重新提交。

## 4. 画像、评估与路径联动

画像通过 8 个固定维度逐项采集。每次对话、纠正和测验联动都创建新画像版本与证据记录。

路径生成先按知识点依赖进行拓扑排序，再结合掌握度确定优先级和预计时长：

- `>=80%`：节点完成，可快速复习。
- `60%-79%`：需要巩固。
- `<60%`：薄弱知识点，优先学习。
- 无记录：先通过课程文章建立基础。

节点状态为 `LOCKED/PENDING/IN_PROGRESS/COMPLETED`。测验提交在同一业务链路更新作答、掌握度和画像，再生成新活动路径版本；旧路径置为 `SUPERSEDED`。

## 5. 多智能体与 RAG

一次资源任务依次执行：

1. 画像分析：提取当前任务需要的画像摘要。
2. 路径规划：明确目标、先修和学习顺序。
3. 内容生成：生成讲解、思维导图和拓展阅读。
4. 练习生成：生成练习题和代码实操。
5. 事实校验：逐项核对检索切片，输出置信度和结论。

RAG 检索以课程独立知识空间为边界。资源引用保存知识文档、切片、摘录、页码和相关度。引用不能支持结论时，资源进入 `NEEDS_REVIEW`，不能直接发布。

任务状态、角色步骤、失败类型和耗时保存在 MySQL。学生端通过 SSE 接收实时事件，连接失败时回退到轮询；刷新后重新读取持久化任务恢复页面。

## 6. 安全设计

- 管理员和学生/教师使用独立账号与会话路径。
- 教育角色由后端 `edu_user_role` 校验，前端角色路由只作为体验补充。
- 教师课程数据范围由 `edu_course_teacher` 控制。
- 学生只能读取已发布课程、章节、本人路径、本人画像和本人生成资源。
- 模型输入过滤手机号、邮箱、证件号、学号、密码、Token、真实姓名和内部用户 ID。
- 内容安全策略支持阻断标记、提示词注入检测和复核置信度阈值，并使用版本号条件更新。
- 文件与预览接口每次读取都重新校验课程访问权，不信任正文中的 URL。

## 7. 幂等、事务与并发

- 测验提交：学生与幂等键唯一，重复请求返回原结果。
- 资源生成：学生与幂等键唯一，失败重试增加尝试次数并保留历史步骤。
- 资源推送：资源、目标类型和目标 ID 唯一，重复推送恢复活动状态。
- 路径：同一学生同一课程只允许一个活动版本；节点完成使用锁定读取和条件更新。
- 课程资料：同一课程附件只建立一条资料关系；同一知识文档同时只允许一个活动入库任务。
- 多表业务写入由 Service 事务维护；模型、向量、对象存储和 LibreOffice 不放入长事务。

## 8. 三端交互设计

- 学生端：课程、学习画像、消息、学习导师、学习资料、个人中心。
- 教师端：课程管理、消息、教学助手、教学资源、个人中心。
- 管理端：运营概览、AI 任务、AI 助手、知识库、AI 基座、内容安全、用户与班级、权限和运维。

三端共享颜色、间距、状态和基础交互语言。比赛提交范围采用桌面 Web 多栏工作区，确认操作统一使用项目弹窗。现有响应式代码继续保留，但不作为本次交付验收范围。

## 9. 部署与可观测性

正式比赛包采用非 Docker 三端部署：Spring Boot 可执行 JAR、教育运营管理端 `dist`、学生/教师端 `dist`。MySQL 与 Redis 由部署机器独立提供，前端静态文件通过 Nginx 或等价服务器托管，并把 `/api`、`/ws` 同源转发到后端。文件默认落到独立本地数据目录，Office 预览按需安装 LibreOffice。

后端健康接口为 `/actuator/health`。结构化日志记录请求号、任务状态、模型、耗时和失败编号，不记录密码、Token、密钥或完整隐私数据。

数据库当前包含 69 个 Flyway 迁移，最新为 `V72`。`V68`、`V69` 补齐 Flowable 7.0.1 身份与事件注册表，`V70` 增加资源反馈，`V71` 增加智能体步骤流式输出，`V72` 增加课程选课关系。现有数据库只允许增量升级；全新迁移验证必须使用独立临时数据库，并保持 `FLOWABLE_DB_SCHEMA_UPDATE=false`。
