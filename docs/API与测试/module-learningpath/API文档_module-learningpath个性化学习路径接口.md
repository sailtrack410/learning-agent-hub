# module-learningpath 个性化学习路径接口

## 一、能力范围

个性化学习路径面向已登录学生，根据课程知识点依赖、当前画像版本、知识点掌握度和既有学习进度，生成有顺序、可解释、可持续更新的课程学习路径。首版推荐资源关联课程章节文章。

## 二、接口清单

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| `GET` | `/api/employee/courses/{courseId}/learning-path` | 查询当前活动路径；首次访问时生成 V1 | 已登录学生 |
| `POST` | `/api/employee/courses/{courseId}/learning-path/nodes/{nodeId}/complete` | 完成当前节点并推进下一节点 | 已登录学生 |

教师账号、未登录用户和非本人路径均不能访问。课程必须存在且处于已发布状态。

## 三、响应结构

```json
{
  "pathId": "8600001",
  "courseId": "8100001",
  "courseName": "Java Web 应用开发",
  "versionNo": 2,
  "profileVersionNo": 11,
  "sourceAssessmentAttemptId": "8660002",
  "generationReason": "完成课程测验后，根据最新掌握度重排薄弱知识点和推荐资源",
  "progressPercent": 50,
  "currentNodeId": "8700005",
  "createdAt": "2026-07-13T14:21:00",
  "todayNodes": [],
  "nodes": [],
  "recommendations": []
}
```

路径节点返回：

- 知识点和章节。
- 学习目标和课程文章资源。
- 预计时长和完成条件。
- `LOCKED`、`PENDING`、`IN_PROGRESS`、`COMPLETED` 状态。
- 生成时掌握度快照和推荐原因。

推荐记录返回知识点、路径节点、资源、优先级、推荐原因和是否已完成。

## 四、路径生成与推进规则

1. 课程知识点按依赖关系拓扑排序；可学习节点中优先安排掌握度较低的知识点。
2. 掌握度达到 80% 的知识点由评估自动标记完成；人工完成记录继续保留。
3. 首个满足前置条件且未完成的节点为 `IN_PROGRESS`，其余节点按前置知识完成情况标记为 `PENDING` 或 `LOCKED`。
4. 学生只能完成当前 `IN_PROGRESS` 节点，越序完成返回 `409`；重复或并发完成同一节点时通过行锁串行处理，返回当前路径且不会连续解锁多个后续节点。
5. `todayNodes` 返回当前节点和后续最多两个待学习节点。
6. 学生提交有效课程测验后，旧活动路径变为 `SUPERSEDED`，系统使用最新画像版本和掌握度生成下一路径版本。
7. 每条推荐原因明确包含无评估记录、当前掌握度、薄弱程度或前置知识依据。

## 五、数据表

- `edu_learning_path`：学生课程路径版本、画像版本、来源测验和生成原因。
- `edu_learning_path_node`：顺序、目标、资源、时长、完成条件、状态、掌握度快照和推荐原因。
- `edu_learning_recommendation`：学生、课程、知识点、路径节点和资源推荐记录。
- `edu_learning_progress`：跨路径版本保留的知识点学习进度和完成来源。

数据库结构由 `V63__add_personalized_learning_paths.sql` 创建。每名学生每门课程只允许一个活动路径，路径版本、节点顺序、节点知识点和学生知识点进度均有数据库唯一约束。

## 六、学生端交互

学生端课程详情提供“我的学习路径”入口，路径页包含：

- “今日学习”：当前学习节点和后续安排。
- “学习路径”：完整依赖顺序和每个节点的状态、目标、资源、时长及完成条件。
- “推荐资源”：仍需学习的课程文章及“为什么推荐”。

课程文章可从路径节点或推荐卡片直接打开；桌面端与 390px 移动端均无横向溢出。
