# 部署与初始化

## 目录

- `docker-compose.yml`：MySQL、Redis、MinIO、Mailpit、后端、前端 Nginx。
- `server/Dockerfile`：后端 Spring Boot 镜像。
- `deploy/nginx/Dockerfile`：构建 `employee-web`、`admin-web` 并交给 Nginx 托管。
- `deploy/nginx/default.conf`：静态资源、`/api/`、`/ws/` 反向代理。
- `deploy/deploy.env.example`：部署变量样板。

## 启动

```bash
cp deploy/deploy.env.example deploy/deploy.env
docker compose --env-file deploy/deploy.env up -d --build
```

访问地址：

- 学生/教师端：`http://localhost/`
- 教育运营管理端：`http://localhost/admin/`
- 后端健康检查：`http://localhost:8080/actuator/health`
- MinIO API：`http://minio.localhost/`
- MinIO 控制台：`http://localhost:9001/`
- Mailpit：`http://localhost:8025/`

## 初始化

数据库表由 Flyway 在后端启动时自动初始化。

迁移 `V11` 初始化 Flowable 流程引擎表，`V68` 初始化 Flowable 身份引擎表，`V69` 初始化 Flowable 事件注册表。部署环境保持 `FLOWABLE_DB_SCHEMA_UPDATE=false`，所有结构均由 Flyway 管理。交付验证必须分别确认现有数据库增量升级和独立空库从零迁移后能够启动，禁止用 Flowable 自动改库掩盖迁移缺失。

首次部署且 `admin_user` 为空时，通过部署环境变量一次性创建首个教育运营管理员：

```text
EDUCATION_ADMIN_BOOTSTRAP_ENABLED=true
EDUCATION_ADMIN_LOGIN=<管理员登录名>
EDUCATION_ADMIN_PASSWORD=<8到64位初始密码>
EDUCATION_ADMIN_DISPLAY_NAME=教育运营管理员
```

后端启动成功并确认管理员可登录后，必须把 `EDUCATION_ADMIN_BOOTSTRAP_ENABLED` 改回 `false` 并重启。初始化只在 `admin_user` 为空时创建账号并授予 `SUPER_ADMIN`；重复启动仅接受同一已启用且已经拥有 `SUPER_ADMIN` 的账号，不会重置密码、恢复已删除或已停用账号，也不会把既有普通管理员提升为超级管理员。

初始化业务数据：

```bash
python3 server/scripts/dev/bootstrap_demo_data.py
```

初始化脚本默认连接：

```text
http://127.0.0.1:8080
```

本地开发和比赛演示环境提供三类演示账号，不得用于生产环境：

| 角色 | 登录名 | 演示密码 |
|---|---|---|
| 教育运营管理员 | `admin.demo` | `Admin@123456` |
| 教师 | `teacher.demo` | `Employee@123456` |
| 学生 | `student.demo` | `Employee@123456` |

正式部署必须禁用或修改演示账号，并为每个实际用户设置独立密码。

## 变量

上线前修改 `deploy/deploy.env`：

```text
MYSQL_PASSWORD
MYSQL_ROOT_PASSWORD
MINIO_ROOT_USER
MINIO_ROOT_PASSWORD
MINIO_ENDPOINT
SPRING_MAIL_HOST
SPRING_MAIL_PORT
SPRING_MAIL_USERNAME
SPRING_MAIL_PASSWORD
WORKFORCE_IM_WEBSOCKET_ALLOWED_ORIGIN_PATTERNS
EDUCATION_ADMIN_BOOTSTRAP_ENABLED
EDUCATION_ADMIN_LOGIN
EDUCATION_ADMIN_PASSWORD
EDUCATION_ADMIN_DISPLAY_NAME
LIBREOFFICE_BIN
FILE_PREVIEW_TIMEOUT_SECONDS
FILE_PREVIEW_MAX_SOURCE_BYTES
FLOWABLE_DB_SCHEMA_UPDATE
AGENT_MODEL_ENABLED
AGENT_MODEL_BASE_URL
AGENT_MODEL_API_KEY
AGENT_MODEL_NAME
AGENT_MODEL_TIMEOUT
AGENT_MODEL_MAX_TOKENS
AGENT_MODEL_TEMPERATURE
```

`MINIO_ENDPOINT` 必须是浏览器和后端容器都能访问的地址。生产环境建议使用对象存储域名。

后端镜像内置 LibreOffice 和 Noto CJK 字体，用于把 `DOC/DOCX/PPT/PPTX` 转换为 PDF 只读预览。转换在业务线程池异步执行，提交接口立即返回，教师端通过状态接口轮询，页面刷新后可继续恢复查询。非容器部署必须自行安装 LibreOffice，并通过 `LIBREOFFICE_BIN` 指向 `soffice`；生产环境应安装课程文档实际使用的字体，否则分页和换行可能变化。单文件默认最大 100 MB，单次转换超时默认 120 秒。

管理端“AI 基座”维护供应商、模型目录、连通状态和默认模型。资源生成任务启动时优先固定使用“启用供应商下启用的默认文本模型”，同一任务的五个智能体不会在执行中途切换模型；管理端没有可用默认文本模型时，才回退到部署环境中的 `AGENT_MODEL_*` 参数。管理端密钥不会写回环境变量，也不会进入任务记录、日志或交付包。部署时应通过密钥管理或受保护的环境变量注入真实密钥，禁止把真实密钥写入模板、源码或归档。

## 常用命令

```bash
docker compose --env-file deploy/deploy.env ps
docker compose --env-file deploy/deploy.env logs -f server
docker compose --env-file deploy/deploy.env restart server
docker compose --env-file deploy/deploy.env down
```

停止应用但保留全部数据库和对象存储数据：

```bash
docker compose --env-file deploy/deploy.env down
```

禁止使用 `down -v`、删除数据卷或重建现有数据库。需要验证全新部署时，应使用独立的新环境和新数据库名称。
