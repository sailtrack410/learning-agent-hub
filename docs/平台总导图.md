# 企业协同人事平台总导图（第一版）

## 一、平台定位
- 员工协同
- 组织沟通
- 团队管理
- 人事流程
- 智能协同
- 系统治理
- 多端统一业务平台

## 二、角色体系
### 1. 业务用户体系
#### 员工
- 完成个人日常协同事务

#### 领导
- 继承员工能力
- 增加团队管理能力

### 2. 系统治理体系
#### 管理员
- 完成系统级治理与配置

### 3. 系统主体体系
#### Agent
- 以系统身份提供问答、预审、提醒与自动化能力
- 不进入业务组织树
- 由管理员在后台创建、配置、授权与审计

## 三、入口与端架构
### 1. C端 / 职工端（Web）
- 使用者：员工、领导
- 面向：日常业务协同
- 特点：信息更完整，适合中低频复杂操作

### 2. 小程序端
- 使用者：员工、领导
- 面向：高频移动操作
- 特点：与 C 端共享同一业务能力，差异只在 UI 与交互

### 3. B端 / 管理后台
- 使用者：管理员
- 面向：系统治理、Agent创建与知识库配置
- 特点：配置化、规则化、治理化

### 4. 后端服务
- 统一权限体系
- 统一流程体系
- 统一业务规则
- 统一数据模型
- 统一消息会话体系
- 统一Agent执行框架
- 统一知识库检索能力

## 四、核心设计原则
- 角色决定能力，组织决定范围
- 组织模型不直接等于流程模型
- 审批人不是固定个人，而是动态解析结果
- 领导是业务用户增强身份，不是后台用户
- 管理员独立于业务用户体系
- C端与小程序共享同一业务域
- 组织架构是可配置的基础模型
- 员工生命周期以状态、事件与生效时间驱动业务联动
- 考勤结果由考勤组、工作日历与班次规则共同计算
- 工龄相关权益以起算日期和规则计算，不直接人工维护结果值
- 用户对话准入由上下级关系与群组关系共同决定
- 群组是组织与业务协同容器，不等于组织树节点
- Agent独立于业务用户体系，以系统身份运行
- Agent最终权限 = Agent自身权限 ∩ 当前用户授权范围 ∩ 当前业务/知识范围
- Agent采用平台化定义，审批预审与知识问答只是首批落地方向

## 五、组织模型
### 1. 组织单元
- 部门
- 上级部门
- 子部门
- 组织层级

### 2. 用户归属
- 一个用户一个主部门
- 管理员不进入业务组织树

### 3. 部门负责人
- 正职负责人
- 组织意义上的第一负责人

### 4. 部门领导成员
- 可存在多个
- 包含副职领导
- 用于审批、排班、管理范围参考

### 5. 汇报关系
- 每个业务用户一个直属上级
- 直属上级必须具备领导身份
- 汇报关系第一版与组织树保持一致

### 6. 组织架构可配置边界
#### 第一版必须支持
- 树状部门
- 用户主部门归属
- 部门负责人配置
- 直属上级配置
- 多领导成员配置

#### 第一版暂不支持
- 多主部门
- 多直属上级
- 虚线汇报
- 复杂矩阵组织

## 六、权限模型
### 1. 数据可见范围
- 员工：仅自己
- 领导：自己部门及子部门
- 管理员：全局
- Agent：按授权范围、当前流程或知识库范围执行

### 2. 操作权限
- 员工：发起、查看、修改个人信息
- 领导：员工能力 + 审批 + 排班 + 团队查看
- 管理员：配置、治理、全局查看
- Agent：问答、预审、提醒、自动执行受配置限制

### 3. 审批资格
- 不固定赋给某个人
- 由流程规则动态计算
- 结合组织关系、角色与审批策略生成

### 4. 会话准入权限
- 员工：可向直属上级、直属下级、同群成员发起对话
- 领导：继承员工能力
- 管理员：治理会话规则与群组策略，不默认进入业务会话
- Agent：仅可进入被授权的会话、群组与业务场景

### 5. Agent执行权限
- Agent以系统身份运行，不继承员工自然身份
- Agent能力由后台创建、配置、发布与停用
- Agent动作必须记录执行日志与审计结果

## 七、审批与流程模型
### 1. 流程类型
- 入职
- 转正
- 调岗
- 调部门
- 请假
- 调休
- 加班
- 离职
- 补卡

### 2. 流程基础结构
- 发起
- Agent预审节点
- 审批节点
- 审批结果
- 流程结束

### 3. 审批人确定原则
- 第一层：直属上级
- 第二层：部门领导层
- 第三层：上级部门逐级升级

### 4. Agent介入原则
- Agent可作为流程预审节点
- 硬规则违规可直接驳回
- 规则不确定或置信度不足时转人工复核
- Agent处理结果必须可追溯、可审计

### 5. 部门审批策略
- 任意一人通过
- 全部会签
- 主管优先，副主管兜底

### 6. 流程状态
- 草稿
- 待审批
- 审批中
- 已通过
- 已驳回
- 已撤回

### 7. 流程原则
- 不写死审批人
- 节点绑定规则，不绑定个人
- 审批链由规则动态生成
