# 企业协同人事平台 —— 开放性实验项目申报材料

---

## 一、项目简介（限300字）

本项目旨在构建一套面向中小型企业的智能协同人事管理平台，以"员工协同 + 组织沟通 + 团队管理 + 人事流程 + 智能Agent"五位一体为核心定位。系统采用Spring Boot模块化单体架构与Vue前端技术栈，覆盖考勤管理、假期余额、申请审批、排班调度、组织人员、协同消息、Agent平台、知识库等完整业务域。

区别于传统HR系统仅做信息记录，本平台将Agent智能体深度嵌入业务链路：在审批流程中引入Agent预审节点，对硬规则违规自动驳回；在会话与群组中支持@Agent进行RAG知识问答；在关键节点触发主动通知与提醒。Agent不是单一聊天机器人，而是模型选择、Prompt模板、工具调用、知识库绑定与工作流编排的组合平台。

系统采用单客户独立部署模式，以Docker Compose交付，适配企业私有化部署需求。第一版开放员工Web端、管理后台及后端服务，后续可按需扩展小程序端。

## 二、主要内容（限1000字）

### 1. 需求分析与业务建模

围绕企业人事协同的完整场景，梳理出三类角色体系：业务用户（员工/领导）、系统管理员、Agent系统主体。确定"角色决定能力，组织决定范围"的核心设计原则，输出组织模型、权限模型、审批流程模型、会话群组模型、Agent执行模型共五大业务模型。

### 2. 系统架构设计

采用模块化单体架构，单Spring Boot应用承载全部业务逻辑。后端按模块划分包与服务边界：公共模块（module-common）、服务契约（module-spi）、认证模块（module-auth）、组织模块（module-org）、后台治理（module-admin）、审批流程（module-workflow）、考勤排班（module-attendance）、假期余额（module-leave）、即时消息（module-im）、文档管理（module-doc）、知识库（module-kb）、Agent平台（module-agent）、外部连接器（module-connector）、消息通知（module-notify）。

前端拆分为员工Web端与管理后台两个独立应用，均采用Vue3技术栈。员工端以消息为默认入口，管理后台以治理配置为核心。

### 3. 数据库设计

主业务数据存MySQL，按业务域设计12类数据模型（组织人员、业务单据、考勤排班、假期余额、配置治理、员工生命周期、会话群组、Agent与知识库、流程运行、平台基础与集成），共计60+核心业务表。知识切片与embedding向量存PostgreSQL+pgvector用于RAG检索，Redis承载登录会话、验证码、限流等缓存能力。

### 4. Agent平台设计（核心亮点）

Agent是平台的差异化能力，采用完整的平台化设计而非单一ChatBot。核心组成包括：
- Agent创建/草稿/测试/发布/停用/回滚的完整生命周期
- 模型选择与路由配置
- Prompt模板版本管理
- 工具白名单绑定与参数校验
- 知识库RAG绑定
- 多触发方式（手动、@会话、流程节点、定时、事件）

Agent执行遵循"三线裁剪"权限模型：Agent最终权限 = 自身权限 ∩ 当前用户授权范围 ∩ 当前业务/知识范围。高风险工具需人工确认，所有执行留审计日志。

### 5. 开发进度安排

| 阶段 | 时间 | 内容 |
|------|------|------|
| 需求与设计 | 第1-4周 | 需求规格说明书、业务建模、架构设计 |
| 基础框架 | 第5-8周 | 工程搭建、认证授权、组织人员 |
| 核心业务 | 第9-16周 | 考勤排班、假期余额、审批流程 |

## 三、项目难点与创新点（限300字）

### 难点

1. **Agent权限的精细化管控**：需要设计"Agent自身权限 ∩ 用户授权 ∩ 业务范围"的三层裁剪机制，既不能越权也不能拒绝合理请求。
2. **审批链动态解析**：审批人不固定绑定个人，需根据组织关系、角色与审批策略实时计算生成，涉及部门领导层、直属上级、上级部门逐级升级等多层规则。
3. **模块间SPI解耦**：Agent需查询组织、假期、知识等分散模块的数据，但不允许直接依赖各模块内部Service，需通过SPI接口层设计受控查询通道。

### 创新点

1. **Agent平台化架构**：不采用单一Prompt对话模式，而是模型→Prompt→工具→知识→工作流的组合定义，可复用的Agent创建发布体系。
2. **双场景Agent落地**：同时覆盖流程预审（硬规则自动驳回）和RAG知识问答（@Agent企业知识检索）两类差异化场景。
3. **模块化单体 + 运行角色分离**：代码层面保持单体简单性，运行层面通过同一镜像不同启动参数分离Web服务与后台Worker。

## 四、预期成果（限300字）

1. **企业协同人事平台系统1套**：覆盖组织人员管理、考勤排班、假期余额、申请审批（含Flowable工作流引擎）、消息群组、Agent平台、知识库等完整功能模块。

2. **技术规范文档**：输出《系统架构设计文档》《核心数据模型定义》《API接口规范》《Agent平台设计白皮书》等核心技术文档。

3. **Docker Compose标准化部署包**：实现一键部署，含Nginx、Spring Boot、MySQL、PostgreSQL+pgvector、Redis、MinIO等全套服务编排。

4. **实验验证**：通过完整业务流程测试（入职→考勤打卡→请假审批→离职全链路），验证Agent预审准确率与RAG问答质量。

5. **成果输出**：申报软件著作权，参与计算机设计大赛或大学生创新创业训练计划。
