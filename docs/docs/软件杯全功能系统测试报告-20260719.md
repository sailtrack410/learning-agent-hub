## 四、缺陷与缺口

### F-01 P0：多智能体资源生成无法稳定完成

固定演示流程要求 5 个智能体最终产出 5 类资源，当前真实运行未通过：

1. 首次重试在画像分析阶段发生 `PROVIDER_ERROR`。
2. 再次重试后，画像分析、路径规划、内容生成分别成功。
3. 练习生成步骤运行 **282579 ms** 后失败，超过代码配置的 180 秒上限约 103 秒。
4. 最终任务进度停在 65%，资源数为 0，只展示泛化错误“模型服务调用失败”。
5. 同一真实模型的同步冒烟和短流式冒烟均通过，说明问题集中在长流式生成、超时取消、外部波动重试或大输出稳定性，而不是模型完全不可用。

影响：固定演示流程第 3 至第 5 步无法完成，教师审核、发布、推送、学生查看和反馈的真实成功链无法继续验收。

建议：优先修复长流式请求的硬超时和取消；增加受限次数的可重试错误重试；记录脱敏后的供应商状态、请求编号和根因类型；对练习生成的输出规模和超时预算重新做压力验证。

相关位置：

- `server/src/main/java/com/workforcehub/learningresource/service/LearningResourceGenerationService.java`
- `server/src/main/java/com/workforcehub/agent/model/OpenAiCompatibleAgentModelClient.java`
- `server/src/main/java/com/workforcehub/agent/model/SpringAiOpenAiChatClientFactory.java`

### F-02 P1：浏览器验收脚本不是独立、可重复的全新环境测试

`scripts/browser-acceptance.mjs` 依赖预先存在的业务状态：

- 学生画像必须已经包含“资源偏好”，全新库初始为 0/8。
- 教师端固定断言 2 条生成任务和 10 条资源。
- 全新库没有这些任务和资源，脚本必然失败。
- 在已经运行后端集成测试的数据环境中，演示数据还可能被测试清理，导致脚本在课程入口提前失败。

影响：开发清单中“浏览器端到端测试覆盖完整演示流程”的完成标记目前不能由可重复测试证明。

建议：由验收脚本创建独立数据库或独立租户数据；显式执行管理员、课程、画像、知识库、测验和资源种子步骤；结束后只清理自己的测试数据；断言业务结果而不是固定历史条数。

### F-03 P1：全新环境缺少可直接演示的管理员与模型初始化

Flyway 会创建角色和权限，但不会创建文档中的 `admin.demo`。正式机制要求首次部署显式设置 `EDUCATION_ADMIN_BOOTSTRAP_*`，而当前本地 `.env` 未配置，因此全新库无法直接登录管理端。教师上传资料后也会因为没有 Embedding 配置而显示“Embedding模型未配置”。

这不是数据库迁移失败，但属于比赛交付的快速启动缺口。评委按默认配置启动时无法直接进入管理端，也无法完成知识库与资源生成。

建议：在比赛交付 README 中提供明确且可复制的首次管理员初始化和模型配置步骤；演示包应提供不含真实密钥的配置校验器，并在启动时明确提示缺少管理员、文本模型、Embedding 和文件根目录。

### F-04 P1：教师端本地上传在中文绝对路径下失败

项目位于中文路径时，学生/教师端本地上传桥把原始绝对路径直接写入 `X-Upload-Path` 请求头，浏览器报错：请求头包含非 ISO-8859-1 字符。管理端已采用 `encodeURIComponent` 与服务端解码，学生/教师端没有采用同样处理。

影响：中文用户名、中文工程目录下的本地开发和比赛演示可能无法上传课程资料或个人文件。切换到 ASCII 文件根目录后本轮上传成功。

相关位置：

- `employee-web/src/composables/usePersonalFileTransfer.ts`
- `employee-web/vite.config.ts`
- 可参考已处理该问题的 `admin-web/src/views/RagflowView.vue` 和 `admin-web/vite.config.ts`

### F-05 P1：前端测试数量不能代表真实交互覆盖

多项管理端和学生端测试通过读取 `.vue` 源码并断言某段字符串存在来判断功能，例如资源重试、教师审核、发布、撤回、推送、超时治理和对话框。这类测试能防止代码被误删，但不能证明组件渲染、点击、异步状态、错误反馈和接口联动正确。

影响：76 项管理端测试和 168 项学生/教师端测试看起来覆盖全面，但关键成功链仍可能只在源码层“存在”，没有运行时证据。

建议：优先为固定演示主链补充真正的组件交互测试和可重复的浏览器 E2E；至少覆盖画像、测验、资源生成、教师审核发布、推送、资源反馈、模型配置和知识库重试。

### F-06 P2：教师端助手文案角色不一致

教师侧导航显示“教学助手”，进入后页面仍显示“学习导师 / 选择你的学习导师”。功能可用，但教师角色语义不一致，演示时容易被评委认为学生端和教师端未完全区分。

### F-07 P2：发布文档统计已过期

现有测试说明书和交付 README 仍记录：后端 415 项、管理端 72 项、学生端 159 项、68 个迁移到 V71。当前实际为：后端 416 项、管理端 76 项、学生端 168 项、69 个迁移到 V72。

需更新：

- `docs/API与测试/软件杯教育版测试说明书.md`
- `deliverables/release/documents/软件杯教育版测试说明书.md`
- `deliverables/release/README.md`

### F-08 P2：MySQL 8.4 超出当前 Flyway 已验证范围

Flyway 9.22.3 每次启动提示 MySQL 8.4 高于其已测试的最高版本 MySQL 8.0。当前迁移实际成功，但提交前应选择项目明确支持的 MySQL 版本，或在获准升级依赖后重新验证；本轮未修改依赖。

5. 把关键前端源码契约测试升级为组件交互和浏览器 E2E。
6. 统一教师助手文案，更新测试说明、发布 README、迁移版本和测试统计。
7. 上述问题修复后，在新的独立空库重新执行：从零迁移、管理员初始化、课程资料入库、画像、测验、路径、5 智能体生成、教师审核发布、推送、反馈、三端浏览器验收和完整构建。

## 六、通过项与发布判定

当前已证明可用的主能力包括：三类账号认证与权限隔离、课程与章节、8 维画像、测验与诊断、掌握度回写、路径重排、知识库上传解析切片、内容安全拦截、管理端治理页面、真实模型基础连通、Office 转换和邮件发送。

但软件杯固定演示的核心卖点是“多智能体生成 5 类资源并经事实校验进入教师治理与学生学习闭环”。该链路当前未通过，所以**现在不建议冻结代码、重新封包或把开发清单中的全功能验收视为完成**。
