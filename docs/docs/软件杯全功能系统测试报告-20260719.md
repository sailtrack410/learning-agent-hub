## 四、缺陷与缺口

### F-01 P0（已修复）：多智能体资源生成无法稳定完成

初始失败历史保留如下：

1. 首次重试在画像分析阶段发生 `PROVIDER_ERROR`。
2. 再次重试后，画像分析、路径规划、内容生成分别成功。
3. 练习生成步骤运行 **282579 ms** 后失败，超过当时配置的 180 秒上限约 103 秒。
4. 最终任务进度停在 65%，资源数为 0，只展示泛化错误“模型服务调用失败”。
5. 同一真实模型的同步冒烟和短流式冒烟均通过，问题集中在长流式 SSE 稳定性、结构化输出截断或非法，以及流式路径缺少受限同步恢复，而不是模型完全不可用。

修复内容：

1. 在管理端 AI 基座配置默认 `TEXT` 模型 `deepseek-ai/DeepSeek-V3.2`。供应商连接配置从部署 `.env` 导入并由模型继承，任务仅保存模型名称，不保存端点或密钥。
2. 管理端结构化输出能力传递到运行时模型快照，五角色请求使用 `response_format=json_object`，并按单一 JSON 对象验收。
3. 流式调用遇到 HTTP `408`、`429`、`5xx`、网络异常或 Spring AI 0.8.1 兼容 SSE 上游空指针时，清除已有不完整正文，在角色共享总超时内最多同步降级一次；认证、权限、解析和总超时错误不重复调用。
4. 流正常结束但为空或不是完整 JSON 对象时，同样最多同步降级一次；同步结果仍非法则以 `INVALID_RESPONSE` 结束，避免把半截内容保存为资源。
5. 总超时覆盖流式与同步降级的完整生命周期，预算分别为画像 `1024 tokens / 60 秒`、路径 `1536 / 60 秒`、内容 `3072 / 180 秒`、练习 `3072 / 180 秒`、事实校验 `2048 / 120 秒`。

真实模型连续复测结果：

| 任务 ID | 画像分析 | 路径规划 | 内容生成 | 练习生成 | 事实校验 | 总耗时 | 资源终态 |
|---|---:|---:|---:|---:|---:|---:|---|
| `1871148872355545088` | 26951 ms | 16296 ms | 99912 ms | 125052 ms | 59062 ms | 327956 ms | 5/5 草稿 |
| `1871149217483849728` | 36503 ms | 16258 ms | 171867 ms | 157575 ms | 38571 ms | 421347 ms | 5/5 草稿 |
| `1871149660124479488` | 10657 ms | 15164 ms | 160556 ms | 118310 ms | 58706 ms | 363909 ms | 5/5 已发布 |

三个任务均完成 5/5 步骤、生成 5/5 类资源并保存知识库引用，终态后 `RUNNING` 残留为 0。第三轮完成教师审核与发布，学生端可以查看全部 5 类资源。三个业务任务总耗时 1113.212 秒，包含任务启动、轮询、发布和学生查看校验的完整验收耗时为 1117.7 秒。

复测期间还发现测试启动器没有持续消费 Maven 日志管道时会阻塞子进程；调整输出方式后验收正常完成，产品任务无异常残留，因此该现象归类为验收环境问题，不计为产品缺陷。

修复判定：**已解决。F-01 不再阻塞固定演示主链路。**

### F-02 P1：浏览器验收脚本不是独立、可重复的全新环境测试

`scripts/browser-acceptance.mjs` 依赖预先存在的业务状态：

- 学生画像必须已经包含“资源偏好”，全新库初始为 0/8。
- 教师端固定断言 2 条生成任务和 10 条资源。
- 全新库没有这些任务和资源，脚本必然失败。
- 在已经运行后端集成测试的数据环境中，演示数据还可能被测试清理，导致脚本在课程入口提前失败。

影响：开发清单中“浏览器端到端测试覆盖完整演示流程”的完成标记目前不能由可重复测试证明。

建议：由验收脚本创建独立数据库或独立租户数据；显式执行管理员、课程、画像、知识库、测验和资源种子步骤；结束后只清理自己的测试数据；断言业务结果而不是固定历史条数。

### F-03 P1：全新环境缺少可直接演示的管理员与模型初始化

本轮验收环境已经在管理端 AI 基座配置并测试默认 `TEXT` 模型，连接参数来自部署 `.env`，因此真实资源生成已可用；但该操作尚未转化为全新交付环境的自动校验或可重复初始化流程。Flyway 会创建角色和权限，但不会创建文档中的 `admin.demo`。正式机制要求首次部署显式设置 `EDUCATION_ADMIN_BOOTSTRAP_*`，未配置时全新库无法直接登录管理端。教师上传资料后也会因为没有 Embedding 配置而显示“Embedding模型未配置”。

这不是数据库迁移失败，但属于比赛交付的快速启动缺口。评委按默认配置启动时无法直接进入管理端，也无法完成知识库与资源生成。

建议：在比赛交付 README 中提供明确且可复制的首次管理员初始化和模型配置步骤；演示包应提供不含真实密钥的配置校验器，并在启动时明确提示缺少管理员、文本模型、Embedding 和文件根目录。

### F-04 P1：教师端本地上传在中文绝对路径下失败

项目位于中文路径时，学生/教师端本地上传桥把原始绝对路径直接写入 `X-Upload-Path` 请求头，浏览器报错：请求头包含非 ISO-8859-1 字符。管理端已采用 `encodeURIComponent` 与服务端解码，学生/教师端没有采用同样处理。

影响：中文用户名、中文工程目录下的本地开发和比赛演示可能无法上传课程资料或个人文件。切换到 ASCII 文件根目录后本轮上传成功。

相关位置：

- `employee-web/src/composables/usePersonalFileTransfer.ts`
- `employee-web/vite.config.ts`
- 可参考已处理该问题的 `admin-web/src/views/RagflowView.vue` 和 `admin-web/vite.config.ts`

### F-05 P1：前端测试数量不能代表真实交互覆盖

多项管理端和学生端测试通过读取 `.vue` 源码并断言某段字符串存在来判断功能，例如资源重试、教师审核、发布、撤回、推送、超时治理和对话框。这类测试能防止代码被误删，但不能证明组件渲染、点击、异步状态、错误反馈和接口联动正确。

影响：76 项管理端测试和 168 项学生/教师端测试看起来覆盖全面，但关键成功链仍可能只在源码层“存在”，没有运行时证据。

建议：优先为固定演示主链补充真正的组件交互测试和可重复的浏览器 E2E；至少覆盖画像、测验、资源生成、教师审核发布、推送、资源反馈、模型配置和知识库重试。
