# 软件杯初赛提交材料缺口清单

> 盘点日期：2026-07-19
> 适用范围：依据当前用户提供的通用初赛要求进行盘点。最终提交内容、文件命名、格式、大小、签章和上传入口，仍必须以当届软件杯官网对应赛题页面的“初赛作品提交要求”为准。

## 一、要求摘要

初赛电子提交内容包括：

1. 源代码。
2. 可执行文件。
3. 相关文档，至少覆盖需求分析、方案设计、测试说明；赛题另有要求时还需一并满足。
4. 演示视频，格式不限，建议控制在 7 分钟以内。
5. 电子报名表。
6. 学生证。

初赛阶段不需要提交纸质证明材料及纸质文档，但不代表可以省略官网要求的电子报名表、学生证扫描件或其他电子证明材料。

## 二、当前结论

当前项目已经具备较完整的技术交付基础，但还不能直接提交。最关键的缺口是：

1. **电子报名表尚未补齐。**
2. **参赛成员学生证扫描件尚未补齐。**
3. **尚未取得并逐项核对当届赛题页面的专属提交要求。**
4. **现有 `deliverables/release/` 和总 ZIP 是旧版本，必须按当前代码重新生成。**
5. **现有发布文档中的测试数量、迁移版本、截图和演示内容需要按最终版本更新。**
6. **关键标准文档目前主要是 Markdown，是否需要同时提供 PDF 或 Word 版尚未确认。为降低评审兼容风险，建议最终补充 PDF 版。**

## 六、提交前执行顺序

### 1. 先锁定官网要求

- [ ] 保存当届赛题页面链接或截图。
- [ ] 记录赛题名称、组别、作品命名规则、文件数量、单文件大小、格式、签章和截止时间。
- [ ] 确认报名表、学生证及其他个人材料要求。

### 2. 冻结代码版本

- [ ] 完成当前未提交修改的功能验收和代码审查。
- [ ] 执行完整验证链路。
- [ ] 检查 Git diff，排除无关文件、凭证、日志、数据库数据和隐私信息。
- [ ] 创建明确的最终提交或版本标签。

完整验证链路：

```bash
cd server && mvn test
cd admin-web && npm run test
cd admin-web && npm run build
cd employee-web && npm run test
cd employee-web && npm run build
```

### 3. 更新文档和演示材料

- [ ] 更新需求、设计、测试、部署、许可证和交付 README 中的版本、日期和统计数据。
- [ ] 更新测试报告中的最终统计行、跳过项和失败说明。
- [ ] 更新浏览器验收截图。
- [ ] 更新演示 PPT。
- [ ] 重录或复核演示视频，确认时长、声音、字幕、真实数据和界面均为终版。
- [ ] 将关键标准文档导出为 PDF，并检查目录、页码、标题层级、图片清晰度和中文字体。

### 4. 补齐个人材料

- [ ] 电子报名表。
- [ ] 全体参赛学生学生证或学籍证明。
- [ ] 官网要求的承诺书、授权书或其他证明。
- [ ] 检查签字、盖章、日期、学校名称、团队名称和成员顺序一致。

### 5. 重新生成交付包

- [ ] 重新生成源码包、后端 JAR、双前端生产文件和部署目录。
- [ ] 重新生成最终 ZIP 和 SHA-256。
- [ ] 在全新目录解压 ZIP。
- [ ] 按 README 从零启动并完成学生、教师、管理员核心流程。
- [ ] 检查 ZIP 内没有 `.env`、真实密钥、Token、数据库备份、日志、缓存、临时截图和未脱敏个人信息。
- [ ] 在赛事平台上传后重新下载或在线预览，确认文件未损坏。

## 七、最短结论

如果只按当前通用要求判断，当前还差：

1. 电子报名表。
2. 学生证或官网认可的学籍证明。
3. 当届赛题专属提交要求核对。
4. 按当前代码重新生成的源代码包与可执行交付包。
5. 与最终版本一致的需求、设计、测试、部署、PPT、截图和演示视频。
6. 最终 ZIP、文件清单和 SHA-256 校验。

其中第 1、2、3 项需要参赛团队人工处理；第 4、5、6 项可以在代码冻结和完整测试通过后由项目构建流程重新生成。
