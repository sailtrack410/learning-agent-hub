# Learning Agent Hub 软件杯教育版数据库设计说明书

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-07-19 |
| 数据库基线 | Flyway 迁移截至 V72（教育主线增量为 V52～V72） |
| 适用版本 | 非 Docker 部署、桌面 Web 三端提交版 |
| 适用范围 | 《Java Web 应用开发》示范课程及教育主线 |

## 1. 编制目的与范围

本文说明软件杯教育版的业务数据模型、核心表职责、主要关系、一致性约束和数据安全边界，用于系统评审、部署验收和后续维护。数据库结构以 `server/src/main/resources/db/migration` 中实际 Flyway 脚本为准。

本文只提炼课程、学生画像、学习评估、个性化学习路径、多智能体资源、知识库、AI 基座、认证权限及文件支撑数据，其他非教育业务表不在本文展开。

## 2. 数据存储组成

| 存储 | 职责 | 数据性质 |
|---|---|---|
| MySQL | 账号权限、课程、画像、测验、路径、生成任务、资源、引用、知识文档主记录和文件元数据 | 业务真相源 |
| Redis | Spring Session、登录失败计数、邮箱验证码及短期状态 | 可过期运行数据 |
| 向量检索存储 | 保存知识切片向量；MySQL 通过 `vector_row_id` 保留对应关系 | 可由知识文档重新生成的检索数据 |
| 本地或对象存储 | 保存课程封面、文章附件和知识库原始文件 | 文件正文；MySQL 保存对象与业务引用 |

三个 Web/服务模块采用同一套业务数据：`server` 负责数据访问和事务，`employee-web`、`admin-web` 只通过后端接口读写，不直接连接数据库。

## 3. 建模约定

- 表名按业务域使用 `edu_`、`kb_`、`agt_`、`auth_`、`admin_`、`org_`、`sys_` 前缀。
- 业务主键主要使用 `BIGINT`；业务编码、幂等键和组合关系另设唯一索引。
- 文本统一使用 `utf8mb4`；结构化编辑器内容、模型配置和规则集合使用 `JSON`、`TEXT` 或 `LONGTEXT`。
- 配置与主数据通常保留 `created_at`、`updated_at`；需要逻辑删除的表使用 `is_deleted`。
- 当前教育表以业务 ID 和索引维护关系，没有在迁移中普遍声明物理外键；引用存在性、归属和级联处理由 Service 事务校验。
- 所有结构变化只新增 Flyway 迁移，不修改已执行脚本。

## 4. 核心关系概览

```text
org_user ── auth_user_account

   ├── edu_user_role ── STUDENT / TEACHER
   ├── edu_course_teacher ── edu_course ── edu_course_chapter ── edu_knowledge_point
   │                              │                         └── edu_knowledge_dependency
   └── edu_course_enrollment ─────┘

STUDENT ── edu_student_profile ── version / dimension / evidence / message
   │
   ├── edu_assessment_attempt ── edu_assessment_answer ── edu_student_mastery
   ├── edu_learning_path ── edu_learning_path_node ── recommendation / progress

edu_course ── edu_course_knowledge_space ── kb_space
           └── edu_course_knowledge_document ── kb_document ── kb_ingest_job / kb_chunk_manifest
```

## 5. 教育核心表设计

### 5.1 课程与教学组织

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_course` | 课程主数据 | `course_code` 唯一；`status` 为 `DRAFT/PUBLISHED`；保存封面引用、目标、先修要求和学时 |
| `edu_course_chapter` | 课程章节及统一文章 | `(course_id, chapter_no)` 唯一；正文为 Tiptap `content_json`；内容类型统一为 `ARTICLE`；章节独立发布 |
| `edu_knowledge_point` | 章节知识点 | `(course_id, point_code)` 唯一；通过 `chapter_id` 归属章节 |
| `edu_knowledge_dependency` | 知识点先修关系 | `(prerequisite_point_id, dependent_point_id)` 唯一；保存课程内有向依赖 |
| `edu_course_teacher` | 课程管理教师 | `(course_id, user_id)` 唯一；角色为 `OWNER/COLLABORATOR` |
| `edu_course_invitation` | 协作教师邀请 | 只保存邀请令牌 SHA-256 摘要；令牌摘要唯一；记录有效期和接受人 |
| `edu_course_enrollment` | 学生选课关系 | `(course_id, student_user_id)` 复合主键；状态为 `ENROLLED` |

课程保存时校验课程编码唯一、章节知识点引用有效、知识点编码不重复，且知识点依赖不能自环或形成环路。课程所有者可删除课程和创建邀请，协作者只参与课程内容管理。

### 5.2 课程知识库与资料绑定

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_course_knowledge_space` | 课程与知识空间一对一绑定 | `course_id` 为主键，`kb_space_id` 唯一 |
| `edu_course_knowledge_document` | 课程、知识文档和原始附件关联 | `kb_document_id` 唯一；`(course_id, attachment_ref_id)` 唯一；可关联章节 |
| `edu_course_knowledge_document_point` | 入库资料与知识点多对多关系 | `(document_binding_id, knowledge_point_id)` 复合主键 |
| `kb_space` | 知识空间主记录 | `space_code` 唯一；保存可见性、解析和向量模型配置 |
| `kb_document` | 知识文档主记录及解析文本 | 记录来源文件、解析器、内容哈希和入库状态 |
| `kb_ingest_job` | 异步解析、分块和向量化任务 | 保存状态、阶段、进度、切片数、失败原因和起止时间 |
| `kb_chunk_manifest` | MySQL 侧知识切片总账 | 文档切片序号唯一；保存切片哈希和向量行 ID |

原始文件、知识文档和向量记录分离：删除或重试入库时，以 MySQL 文档主记录为依据重建检索数据，生成资源引用仍能回溯到文档与切片。

### 5.3 学生画像

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_student_profile` | 每名学生的当前画像 | `student_user_id` 唯一；`current_version` 指向当前逻辑版本 |
| `edu_student_profile_version` | 画像变更历史 | `(profile_id, version_no)` 唯一；触发类型为对话、纠正或测验 |
| `edu_student_profile_dimension` | 当前维度结论 | `(profile_id, dimension_code)` 唯一；保存结论、置信度和依据摘要 |
| `edu_student_profile_evidence` | 维度结论证据 | 关联画像版本、维度、证据类型和内容 |
| `edu_student_profile_message` | 画像对话记录 | 保存 `USER/ASSISTANT` 消息及关联维度，不保存模型内部推理过程 |

每次有效回答、主动纠正或测验联动都会形成可追溯版本；资源生成任务只复制当前任务所需的脱敏画像快照。

### 5.4 测验与掌握度

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_assessment` | 课程或章节测验 | 状态为 `DRAFT/PUBLISHED`；保存总分和建议时长 |
| `edu_assessment_question` | 测验题目 | 关联知识点；支持单选、多选和判断题；答案与选项使用 JSON |
| `edu_assessment_attempt` | 学生一次测验提交 | `(student_user_id, idempotency_key)` 唯一；同一测验尝试序号唯一 |
| `edu_assessment_answer` | 单题作答结果 | `(attempt_id, question_id)` 唯一；保存得分、正误、错误类型和用时 |
| `edu_student_mastery` | 学生知识点掌握度 | `(student_user_id, course_id, knowledge_point_id)` 唯一；保存掌握度及作答统计 |

测验提交、答案入库、掌握度更新、画像更新和学习路径重排位于受控业务链路中；重复幂等键返回同一次作答结果，不重复累计。

### 5.5 个性化学习路径

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_learning_path` | 学生课程路径版本 | `(student_user_id, course_id, version_no)` 唯一；`active_flag` 保证同课程仅一个活动版本 |
| `edu_learning_path_node` | 路径节点 | 路径内顺序和知识点均唯一；状态为 `LOCKED/PENDING/IN_PROGRESS/COMPLETED` |
| `edu_learning_recommendation` | 路径资源推荐 | 每个路径节点一条活动推荐；保存优先级和可解释理由 |
| `edu_learning_progress` | 学生知识点累计进度 | `(student_user_id, course_id, knowledge_point_id)` 唯一；记录手动或测验完成来源 |

路径按知识依赖拓扑排序生成。完成测验后，旧活动路径转为 `SUPERSEDED`，新版本保存触发作答 ID 和生成时画像版本。

### 5.6 多智能体资源生成与治理

| 表名 | 主要职责 | 关键字段与约束 |
|---|---|---|
| `edu_resource_generation_task` | 一次学生资源生成请求 | `(student_user_id, idempotency_key)` 唯一；保存脱敏画像快照、模型、进度、失败信息和耗时 |
| `edu_resource_generation_step` | 五角色执行轨迹 | `(task_id, attempt_no, role_code)` 唯一；保存状态、摘要、实时输出、模型和耗时 |
| `edu_generated_resource` | 生成后的学习内容 | `(task_id, resource_type)` 唯一；包含 5 类资源、校验状态、置信度和发布状态 |
| `edu_generated_resource_citation` | 资源事实引用 | `(resource_id, kb_chunk_id)` 唯一；保存文档、切片、摘录、页码和相关度 |
| `edu_content_safety_policy` | 教育内容安全策略 | 固定策略记录；保存注入检测开关、复核阈值、阻断标记和乐观锁版本 |
| `edu_generated_resource_push` | 教师定向推送 | `(resource_id, target_type, target_id)` 唯一；目标为学生或班级 |
| `edu_resource_learning_record` | 学生查看记录 | `(resource_id, student_user_id)` 唯一；累计查看次数和首末查看时间 |
| `edu_resource_feedback` | 学生资源反馈 | `(resource_id, student_user_id)` 唯一；支持有帮助、过难、过易和不相关 |

任务状态为 `PENDING/RUNNING/SUCCEEDED/FAILED`。资源先进入草稿，教师完成修改或审核后才能发布；已发布资源可撤回。失败重试通过 `attempt_no` 形成新一轮步骤，不覆盖原任务身份。

## 6. 必要支撑表

### 6.1 身份、组织与后台权限

| 表组 | 表名 | 用途 |
|---|---|---|
| 学生/教师身份 | `org_department`、`org_position`、`org_user`、`auth_user_account`、`edu_user_role` | 学院班级、人员、登录账号和 `STUDENT/TEACHER` 教育角色 |
| 管理员 RBAC | `admin_user`、`admin_role`、`admin_permission`、`admin_user_role`、`admin_role_permission` | 独立管理员账号、角色和权限点关系 |

密码字段保存 BCrypt 哈希。管理员与学生/教师账号分表，避免两类会话身份互相替代。

### 6.2 文件与预览

| 表名 | 用途 |
|---|---|
| `sys_file_object` | 文件物理对象、哈希、大小、上传和扫描状态 |
| `sys_attachment_ref` | 文件与课程、文章等业务对象的引用及可见范围 |
| `sys_upload_ticket` | 两阶段上传票据和客户端幂等标识 |
| `sys_file_upload_policy` | 课程资源等场景的扩展名、MIME 和大小限制 |
| `sys_attachment_preview` | Office 原文件与 PDF 预览文件的转换状态关系 |

课程资源读取不只依赖附件 ID，还会重新检查教育角色、课程成员关系、课程/章节发布状态和附件归属。

### 6.3 AI 基座、Agent 与审计

| 表名 | 用途 |
|---|---|
| `agt_llm_provider` | 模型供应商、端点、凭证配置和最近连通性结果 |
| `agt_llm_model` | 模型类型、模型 ID、能力标志、默认模型和测试结果 |
| `agt_agent`、`agt_agent_version` | AI 助手定义、版本、提示词和流程配置 |
| `agt_knowledge_binding` | 助手版本与知识空间绑定 |
| `agt_task`、`agt_audit_log` | 通用 Agent 任务状态和执行审计摘要 |
| `sys_audit_log` | 管理和系统操作审计基础记录 |

AI 基座优先使用后台启用的默认文本模型；没有可用默认模型时，运行时服务才回退到部署环境中的 `AGENT_MODEL_*` 配置。任何真实 API 密钥都不属于源码或比赛公开文档。

## 7. 一致性、幂等与并发设计

- 课程编码、知识点编码、章节序号等业务唯一性由数据库唯一索引兜底。
- 测验提交、资源生成、上传票据使用调用方幂等键，防止重复点击产生重复数据。
- 课程选课、资源推送、学习记录和反馈使用复合唯一键或 upsert，重复操作复用原记录。
- 同一学生同一课程只允许一条活动路径；历史路径通过空 `active_flag` 保留。
- 内容安全策略使用 `version_no` 条件更新，避免管理员并发覆盖。
- 多表写入在 Service 层设置事务；模型调用、文件转换和向量化不放入长事务。

## 8. 索引与查询设计

- 列表索引优先覆盖“用户/课程 + 状态 + 时间”，例如生成任务、学习进度和资源列表。
- 路径节点使用 `(path_id, sequence_no)` 支持顺序读取。
- 教师数据范围使用 `(user_id, course_id)` 查询课程成员关系。
- 学生资源与任务以 `student_user_id` 为首列，防止跨用户扫描。
- 知识切片按文档和序号唯一，引用按资源 ID 查询。
- 状态与时间索引服务后台任务筛选、入库进度和失败任务治理。

## 9. 数据安全与生命周期

- 登录密码只保存 BCrypt 哈希；课程邀请只保存令牌摘要。
- 资源请求、反馈和画像快照进入模型链路前过滤邮箱、手机号、身份证号、学号和疑似凭证。
- 学生画像、作答、路径、任务和反馈以 `student_user_id` 隔离；教师数据以 `edu_course_teacher` 隔离。
- API 密钥字段仅供受限后台配置和运行时调用，普通响应只返回“是否已配置”，不回传密钥内容。
- 任务轨迹保存必要状态、结果摘要和最终内容，不保存模型内部推理过程。
- 正式部署应对 MySQL、Redis、文件目录和环境配置实施最小权限、访问控制、备份保护和密钥轮换。

## 10. 迁移、备份与恢复要求

1. 后端启动前准备空库或现有兼容库，并为应用账号授予所需 DDL/DML 权限。
2. 启动时由 Flyway 按 `flyway_schema_history` 增量执行迁移，目标版本为 V72。
3. 禁止手工修改已执行迁移、清空现有数据库或通过 `schema-update` 绕过 Flyway。
4. 升级前备份 MySQL、文件存储及部署环境配置；Redis 会话可按运行状态单独处理。
5. 恢复后核对 Flyway 版本、教育核心表数量、示范课程、默认模型状态和知识入库状态，再开放 Web 入口。

## 11. 设计核验依据

- 教育结构：Flyway `V52__add_education_course_foundation.sql` 至 `V72__add_course_enrollment.sql`。
- 身份与权限：Flyway V1、V32、V45、V46、V53、V54、V65。
- AI 与知识库：Flyway V20、V23～V28、V43、V44、V47、V48、V60、V67。
- 文件支撑：Flyway V1～V7、V17、V18、V29、V56、V59。
- 业务一致性：当前 `course`、`profile`、`assessment`、`learningpath`、`learningresource` Service 与 Repository 实现。
