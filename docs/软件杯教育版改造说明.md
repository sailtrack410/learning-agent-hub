# 软件杯教育版改造说明

## 仓库定位

- 当前仓库：高校个性化学习多智能体参赛版。
- 原始仓库：`../workforce-hub`，继续保留人事协同产品方向。
- 当前分支：`codex/education-adaptation`。
- 两个仓库后续独立修改，不再相互覆盖运行配置和业务代码。
- 教育版运行库默认使用 `learning_agent_hub`，自动化测试库默认使用 `learning_agent_hub_test`，不得连接或清理原项目数据库。

## 保留并复用

- Spring Boot 模块化单体、认证、RBAC、审计、消息、文件和任务基础设施。
- Agent 工作流、工具调用、任务执行、超时治理和人工确认能力。
- RAG 知识库、文档入库、向量检索和引用能力。
- Vue 3 双端结构：员工端改造为学生端，管理端改造为教师与课程运营端。

## 隐藏或退出参赛主流程

- 考勤、请假、假期、岗位和人事审批。
- 员工入离职、组织人事治理等比赛无关导航。
- 文件清理、消息投递等运维功能只保留在管理端次级入口，不进入演示主线。

## 必须新增的比赛核心能力

1. 对话式学生画像：至少覆盖知识基础、学习目标、掌握度、易错点、认知风格、资源偏好、学习节奏和实践能力。
2. 多智能体资源生成：画像、规划、内容、练习、校验智能体协作，生成讲解文档、思维导图、题库、代码实操和拓展阅读至少五类资源。
3. 动态学习路径：按知识点依赖、学生掌握度和反馈动态调整学习顺序。
4. 资源推荐：将生成资源编排进学习路径，并通过学生端和消息能力推送。
5. 防幻觉与内容安全：知识库引用、来源展示、校验智能体、置信度和教师审核。
6. 生成体验：流式输出、任务进度、失败重试和可恢复的后台生成任务。

## 数据与演示范围

- 首门完整课程采用《Java Web 应用开发》。
- 构造课程大纲、知识点依赖、教学文档、代码案例、题库和错误案例数据集。
- 演示流程固定为：画像构建 -> 路径规划 -> 多智能体生成 -> 事实校验 -> 资源推送 -> 练习评估 -> 路径更新。
